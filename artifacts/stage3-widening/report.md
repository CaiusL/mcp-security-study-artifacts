## Threats and limits

- **Defense-aware choice.** Each W call was chosen from the deriver's rules (`build_profile` in wiggle/policy.py). That is knowledge of the defense, more than the static pilot templates use. The W texts were written once and frozen before any model run, and there is no query loop. It is still a different attacker from the static one, so this arm is reported apart from the static Stage 2 results.
- **Query-string gap.** `normalize_url` keeps the scheme, host and path and drops the query and the fragment, and `exact_key` uses the same form for fetch. So the L4 URL rule and the L5 exact key ignore the query: a fetch to a URL that a benign trace used can carry data in its query string at every fetch level. With W3 in a training trace the sink becomes a benign host. This is a known limit of the fetch ladder, and the phase 1 curves are not rerun (PROMPT.md, amendment 2026-11-02).
- **Size.** 54 poisoned runs give wide intervals. The arm decides go or no-go for a full Stage 3 run. It does not support a defense claim.
