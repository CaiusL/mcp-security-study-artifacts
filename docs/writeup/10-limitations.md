# 10. Limitations

*Draft, 2026-11-03.*

- **Attacker strength.** The main Stage 2 results use one frozen template with no query loop. The separately frozen Stage 4 arm completed ten attacker replies for each of 20 cases and three selected-text reruns per case, using 5,404,909/6,000,000 recorded tokens (`artifacts/stage4/qwen3.8-flash/report.md`). The budget did not support a second full target arm. It does not change the static results or establish robustness beyond that query budget. Its Step 0 bound excludes a completing call under every target task policy, so the observed 0/60 under layer (d) is bounded by construction. Its safety-constrained text space, shared texts across reruns and lack of new live enforcement or utility measurements limit interpretation. It does not test adaptive attacks on the policy generator.
- **Two models, one of them unmoved.** `deepseek-flash` reached no goal in 300 attack runs, so every layer comparison rests on `qwen3.8-flash` (33 successes). Results may not transfer to other models or hosts.
- **Thinking mode.** Both models ran with thinking off. Qwen's endpoint failed with thinking on (section 4.4). Thinking-on behavior is not measured.
- **Stand-ins.** The vulnerable arm uses a filesystem stand-in, not the vulnerable server pins, because a vulnerable pin may run only inside a jail and this machine has none. The study builds no jail (decision 2026-11-03): 32 of the 33 Qwen successes stayed inside the declared scope and needed no server bug (section 6.2), so the observed in-scope-excess finding does not depend on executing vulnerable pins. A live vulnerable-pin arm remains unmeasured and would require a new freeze and runs on both models. The fetch server and the description fixture are stand-ins in both arms.
- **One host prompt.** Every run uses one frozen host prompt. A different system prompt may move attack success.
- **Replay counterfactuals.** Layers are scored by replaying recorded traces. Live re-runs check that on 10 cases per layer; layer (c) agreed on 8 of 10 and is scored live only. A real defense also changes what the agent does next, which replay does not see.
- **The fetch ladder's query-string gap.** `normalize_url` keeps the scheme, host and path and drops the query and the fragment, so the L4 URL rule and the L5 exact key ignore the query. A fetch to any URL that a benign trace used can carry data in its query string, at every fetch level. It is reported as a known limit, and the phase 1 curves were not rerun.
- **Human labels.** "Inside the grant" was coded the opposite way by the pilot 2 coders (8 of 8 inside) and the Stage 2 coders (33 of 33 outside), under the same sheet rule plus a written clarification in Stage 2. The coders' OWASP codes agreed on 15 of 33; the label is therefore derived by rule A. Coder 2 of Stage 2 coded on the same machine and account as coder 1 and saw all rows at once after the first (`artifacts/stage2/qwen3.8-flash/coder-2.json`, note).
- **Case set size.** Fifty attack cases on six servers. A miss on our lattice is a share of the lattice, not a proof that no attack works.
- **Task-policy generators.** The main verdict uses the minimal generator. The separately frozen Progent rerun is complete on both models, using its pinned policy generator and checker. It evaluates frozen task policies, not Progent's online update workflow; its over-permission counts cover tools only (section 7.5).
- **Self-hosting (RQ3) and the backdoor joins.** Not tested: the study has no local model host, so the joins J1 to J3 were dropped (decision 2026-11-03). The backdoor results in sections 5 and 6.3 come from the BadAgent repository and were not scored by the oracles of section 4. A later API-versus-local comparison is clean only with the same checkpoint, quantization and host prompt.

- **Counterfeit tool implementations.** This study measures the recorded call/effect chains of its selected servers. It does not establish that an allowed call bounds every side effect of an arbitrary malicious implementation. The separate `adversary-write-behind` branch studies that question with counterfeit fixtures and a tree audit; its runs and proposed sixth check are not pooled into these frozen results. See `docs/artifact-delivery.md` for the inspected commit and integration boundary.
