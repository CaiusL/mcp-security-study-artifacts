# Shared Traces Expose Which MCP Defenses Hold

**No published study scores a static scanner, server-side checks, a trace-learned least-privilege policy, a task-conditioned policy and a data-flow rule against one shared set of MCP attack traces, so the core of this study (record each attack once, then attribute each success to the layer that would have blocked it) fills a real gap.** The nearest work runs each defense as a separate live run (AgentDojo, MSB, MCP-SafetyBench, MELON, Progent), ablates runtime components on only 10 synthetic cases (HCP), or maps attacks to enforcement layers on paper with no block rates (MCP-DPT). Three more gaps are open: no paper reports an attack success rate (ASR) for injections in git commit messages or MCP memory-graph entities; no paper plots a nested, trace-derived strictness ladder against held-out utility under injection; and no paper injects a task-conditioned policy generator at "policy birth". Attacks on Progent's policy *updater* already exist, and they gained almost nothing against weak attackers. The in-scope-misuse hypothesis splits on the evidence: **11 of 18 attack-measurement papers report successes that are mainly in-scope misuse, but only 8 of 40 catalogued incidents are, against 23 boundary breaks**. The two tallies are biased in opposite directions (benchmarks define success as misuse of a legitimate tool; a CVE needs a bug), so the claim the evidence supports is narrower: once server bugs are patched, the residual injection risk is in-scope misuse. The design should change to match: pin patched servers and add a vulnerable arm, give each canary goal a boundary-crossing alternative so "in scope" is not true by construction, label every successful trace with a three-field coding rule, learn policies on held-out tasks, use condition-blind deterministic oracles, check offline replay against live re-runs, and add one adaptive attack round.

## No benchmark attributes one trace set to five layers

AgentDojo sets the conventions reviewers will expect. It pairs 97 user tasks with 629 security test cases and reports benign utility, utility under attack and targeted ASR together ([arXiv](https://arxiv.org/abs/2406.13352)). Its results page calls itself "not a leaderboard" and shows how much the model alone moves the baseline: undefended gpt-4o reaches **47.69% ASR**, claude-3-5-sonnet **1.11%** ([AgentDojo results](https://agentdojo.spylab.ai/results/)). An audit of AgentDojo, ASB and InjecAgent found implementation flaws that change headline numbers; ASB's combined attack on GPT-4o fell from **73.58% to 9.25%** once attacker tools stopped being force-injected into every sub-task ([arXiv](https://arxiv.org/html/2510.05244v2)). The study should copy AgentDojo's task-by-injection pairing and metric triplet, not its code.

MCP-native security benchmarks now exist, but none matches the study's tool surface. MSB (ICLR 2026) runs real tools through an MCP client with FileSystem and DesktopCommander servers, judges attacks from workspace state and reports an average **40.35% ASR** over 10 models ([arXiv](https://arxiv.org/html/2510.15994v2)). MCP-SafetyBench (ICLR 2026) uses real third-party servers with dual task and attack labels over 3 repetitions; ASR spans **29.80–48.16%** across 13 models, but task success is only **8.98–21.22%**, which would pin the utility axis of any ASR-vs-utility curve near the floor ([arXiv](https://arxiv.org/html/2512.15163v2)). MCPTox, reported as AAAI 2026, is the reference corpus of poisoned tool descriptions: 1,348 cases over 45 live servers and 353 tools ([arXiv](https://arxiv.org/abs/2508.14925)). MCPSecBench targets protocol and host bugs on custom vulnerable servers ([arXiv](https://arxiv.org/abs/2508.13220)). **None of them uses the reference filesystem, git, fetch, memory and time servers together, and none plants injections in commit messages or memory-graph entities.**

Multi-defense comparisons exist only as separate runs inside single papers. MELON compares seven defenses on identical AgentDojo runs ([arXiv](https://arxiv.org/html/2502.05174v4)), and Progent compares six baselines ([arXiv](https://arxiv.org/html/2504.11703v3)). LlamaFirewall reports the only measured layer combination found, a classifier plus an alignment auditor that cut ASR from **17.63% to 1.75%** while utility fell from 47.73% to 42.68% ([arXiv](https://arxiv.org/html/2505.03574v1)). AutoDojo runs ten defenses against five models under adaptive attacks and finds static benchmarks "significantly overestimate" defense efficacy ([arXiv](https://arxiv.org/abs/2606.15057)). The nearest thing to layer attribution is the HCP runtime paper, which ablates components on **10 cases**: a naive runtime permits all 10 attacks, practice-informed mitigations permit 6, and HCP blocks all ([arXiv](https://arxiv.org/abs/2606.29073)). MCP-DPT assigns attacks to six architectural enforcement layers and says no prior work does so, but it reports no measurements ([arXiv](https://arxiv.org/abs/2604.07551)). A label audit of an MCP campaign with 10,200 execution rows found the grader had leaked condition metadata into its labels; condition-blind relabeling turned **58 "attack success" labels into authorized benign completions** ([arXiv](https://arxiv.org/abs/2608.12880)). That audit is the clearest prior work that separates true violations from in-scope behavior, and its warning applies directly to the study's oracle.

The table maps each study element to its closest prior work (each entry is cited in the sections that follow).

| Study element | Closest prior work | What it leaves open for this study |
|---|---|---|
| Harness on real MCP servers | MSB; MCP-SafetyBench | Reference git, fetch, memory, time servers; canary oracles; replayable traces |
| Same-trace, multi-layer attribution | MELON and Progent same-run tables; HCP ablation (10 cases); MCP-DPT taxonomy | Five different layers scored on one MCP trace set, with first-blocker and unique-blocker attribution |

The practical build path is a thin harness on the official MCP client SDK that copies AgentDojo's structure. MSB is the closest MCP-native base, but its repository has 5 commits and no documented defense hook ([MSB repo](https://github.com/dongsenzhang/MSB)). The only AgentDojo-to-MCP bridge has 0 stars, maps tools by heuristic name matching, and misses server-side state in its post-task checks ([agentdojo-mcp](https://github.com/basitalisandhu/agentdojo-mcp)). Running the ladder on a small AgentDojo slice as well gives a cheap comparability anchor. ROPE, AgentArmor, and Khan, AlKhanbashi, and Mohamed, Computers 15(9):570, were read in full on 2026-10-25. The notes are in `docs/injection-protocol.md` and `docs/related_work.md`. None of those texts is a same-trace attribution of a scanner, a server patch, and a Needed ladder. No "first" claim follows from that reading.

## Papers favour in-scope misuse; incidents favour boundary breaks

Read as a body of attack measurements, the literature supports the hypothesis. Of 18 attack-measurement papers and reports classified at class level, **11 report successes that are mainly in-scope misuse** (an allowed tool on an allowed resource), 4 are mixed, and only 3 are mainly boundary or host bugs. In-scope success runs high without any bug. MCPXKIT's file add, modify and retrieve attacks succeeded in **10 of 10 runs** because those operations needed no user confirmation ([arXiv](https://arxiv.org/html/2508.12538v2)). A compromised server's covert logging tool was invoked autonomously in **90.7% of 360 interactions** ([ICML 2026 workshop](https://icml.cc/virtual/2026/67871)). Implicit tool poisoning steered agents to legitimate high-privilege tools with up to **84.2% ASR** ([arXiv](https://arxiv.org/abs/2601.07395)). Root-cause analyses agree: the IEEE S&P 2026 Parasitic Toolchain study names missing context–tool isolation and missing least privilege, not server bugs ([arXiv](https://arxiv.org/abs/2509.06572)), and Invariant's GitHub exploit was "not a flaw in the GitHub MCP server code itself" ([Invariant](https://invariantlabs.ai/blog/mcp-github-vulnerability)). The two papers that measure boundary failure report bug prevalence, not agent ASR. MCP-FSD found unexpected filesystem capability in **16.4% of 4,806 triaged servers** and validated 150 vulnerable instances ([arXiv](https://arxiv.org/abs/2610.22301)). ToFu found 64 path-traversal, 7 SSRF and 3 command-injection bugs among 253 verified bugs, although its abstract gives a different count (343 tools) ([arXiv](https://arxiv.org/html/2610.13651)).

Read as a public record, the evidence refutes it. A catalogue of 40 MCP incident, disclosure and CVE rows from April 2025 to October 2026 classifies **23 (58%) as boundary breaks, 9 (22%) as supply chain and only 8 (20%) as in-scope misuse**. In the 24 rows where an agent acted on injected content, 11 (about 45%) used only in-scope calls and 13 needed a bug. Every confirmed or reported in-the-wild harm is supply chain or a boundary break: the postmark-mcp package that silently copied every email to an attacker ([The Hacker News](https://thehackernews.com/2025/09/first-malicious-mcp-server-found.html)), an exposed nginx-ui MCP endpoint whose exploitation claim rests on a secondary source ([CVE record](https://www.cve.org/CVERecord?id=CVE-2026-33032)), and Asana's accidental cross-tenant exposure ([BleepingComputer](https://bleepingcomputer.com/news/security/asana-warns-mcp-ai-feature-exposed-customer-data-to-other-orgs/)). **No in-scope-misuse attack via MCP has been confirmed in the wild**; every such row is a researcher proof of concept or a vendor-fixed CVE. An NVD keyword query found 516 CVE records that name MCP, rising from 6 per month in May 2025 to 108 in September 2026, and **only 25 of them mention prompt injection** ([NVD API](https://services.nvd.nist.gov/rest/json/cves/2.0?keywordSearch=MCP%20server)).

| Measure | Attack-measurement papers (n = 18) | Public incident record (n = 40) |
|---|---|---|
| Mainly in-scope misuse | 11 | 8 (20%) |
| Mixed | 4 | not used as a class |
| Boundary or host bug | 3 | 23 (58%) |
| Supply chain (attacker owns the component) | counted inside "mixed" | 9 (22%) |
| Agent-driven subset | all except 2 bug censuses | 24 rows: 11 in-scope only, 13 needed a bug |
| No agent decision in the path | 0 | 15 |

The tallies disagree because they count different things, and each one's definition of success biases it. Benchmarks build in-scope misuse into the metric: MCPTox counts a call to the poisoned tool itself as failure and requires a call to a separate legitimate tool ([arXiv](https://arxiv.org/html/2508.14925v1)), so in-scope misuse is the only success it can see. CVEs build boundary breaks into the record: a CVE needs a bug, and in-scope misuse gets labelled "by design". Cursor called the AgentFlayer Jira attack a known issue ([Willison](https://simonwillison.net/2025/Aug/9/when-a-jira-ticket-can-steal-your-secrets/)); Anthropic declined to fix the LayerX calendar case because the user had allowed the tools to run without prompts ([Infosecurity](https://www.infosecurity-magazine.com/news/zeroclick-flaw-claude-dxt/)); OX lists Anthropic's MCP STDIO behavior as "won't be patched" ([OX Security](https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem/)); the GitHub MCP exploit has no CVE. Incentives and detection add to the skew. Bounties and CNAs reward bugs, most in-scope write-ups come from vendors that sell guardrails, and in-the-wild misuse leaves authorized-looking logs; Microsoft's invoice-agent example was a case where every single step was "legitimate" ([Microsoft](https://www.microsoft.com/en-us/security/blog/2026/06/30/securing-ai-agents-ai-tools-move-from-reading-acting/)). Denominators differ too: 15 of the 40 incident rows have no agent in the path, so no agent-side layer could apply to them.

Both tallies are right about different populations. The papers measure what an agent can be steered to do against a correctly implemented server; the incident record measures where disclosed bugs live. They converge on residual risk: every boundary-break row has a patch, while the in-scope rows were declared known, by design or structural. The line between the classes also moves. Claude Code's CVE-2025-55284 put harmful commands on a default allowlist, in scope by the host's own grant, until the vendor narrowed it ([GHSA](https://github.com/anthropics/claude-code/security/advisories/GHSA-x5gv-jw7f-j6xj)). Two 2026 CVEs treat an MCP tool that accepts any attacker-supplied host as an improper endpoint restriction ([CVE-2026-18655](https://www.cve.org/CVERecord?id=CVE-2026-18655); [CVE-2026-53957](https://www.cve.org/CVERecord?id=CVE-2026-53957)). Under that CNA reading, a fetch tool that accepts any URL is itself a bug, which moves the study's exfiltration goal onto the borderline. A defensible sentence for the paper is: "Public disclosures are dominated by boundary breaks (58% of 40 catalogued cases), but CVE criteria exclude in-scope misuse by construction; among agent-driven cases, about 45% used only in-scope calls, and no server patch fixed any of them."

The same selection bias threatens the study itself (this is an inference from the evidence above). All three canary goals are in scope by design: the secret sits inside the root, the `.sh` file goes into an allowed directory, and the canary leaves through the fetch tool. A high in-scope share would then be partly the study's own construction, the same artefact that inflates the paper tally. To test the hypothesis rather than assume it, each goal needs an alternative path that crosses a boundary: a second secret outside the root, a write target outside the allowed directory, a `git_add` of an out-of-repo file. The reference servers' history shows these paths are real on unpatched versions: filesystem CVE-2025-53109 (symlink escape) and CVE-2025-53110 (prefix collision) ([GHSA 53109](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-q66q-fx2p-7w4m); [GHSA 53110](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-hc55-p739-j48w)), and mcp-server-git CVE-2025-68143, -68144 and -68145 ([GHSA 68143](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-5cgr-j3jf-jw3v); [GHSA 68144](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-9xwc-hfwc-8w59); [GHSA 68145](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-j22h-9j4x-23w5)) plus CVE-2026-27735, where `git_add` staged files outside the repository ([GHSA](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-vjqx-cfc4-9h6v)).

## Each layer has a documented blind spot

### Scanners read artifacts, and most injections carry none

Every independent scanner evaluation reports low recall, high false positives, or both. MCPZoo ran 8 scanners on 37,288 runnable servers: 96.89% of servers were flagged by at least one scanner, yet average **precision was 45.53% and recall 24.17%**, and pairwise agreement was only **15.66%** (Jaccard) ([arXiv](https://arxiv.org/html/2607.11086v1)). In the ACE corpus, Cisco's mcp-scanner in offline YARA mode reached **0.159 recall at 16.3% false-positive rate**; 52 of 82 malicious fixtures changed server behavior without changing `tools/list`, and **51% of the corpus delivered payloads through files, web responses, prompts, memory or retrieved documents, with no MCP server to scan**, which the authors call "a structural blind spot of the scanner class" ([arXiv](https://arxiv.org/html/2609.28915v1)). On 120 generated malicious servers, mcp-scan detected 4 and AI-Infra-Guard 63 ([arXiv](https://arxiv.org/html/2509.24272v1)); MCPScan and MCP-Shield never flagged direct preference-manipulation servers ([arXiv](https://arxiv.org/html/2505.11154v2)); optimized implicit poisoning pushed an LLM detector's detection rate to **0.3%** ([arXiv](https://arxiv.org/abs/2601.07395)). Pluto Security built a credential thief and an RCE server with benign weather metadata, and Cisco, Snyk and MCP-Shield all missed both ([Pluto Security](https://pluto.security/blog/malicious-mcp-servers-clean-scans/)). False positives are the other cost: one 33-server audit judged about 78% of Cisco's detections false ([AppSec Santa](https://appsecsanta.com/research/mcp-server-security-audit-2026)), and a competing scanner's author (who declares "we are not neutral") found that 0 of 20 sampled MCP-Shield blocks on registry servers held up ([dev.to](https://dev.to/alexar76/we-ran-three-mcp-security-scanners-on-a-tool-poisoning-benchmark-and-986-real-servers-1klb)). Scanners do work on explicit markers: with an injection prefix added, rule scanners caught 222–225 of 225 poisoned tools, against 11–19% without it ([dev.to](https://dev.to/alexar76/we-ran-three-mcp-security-scanners-on-a-tool-poisoning-benchmark-and-986-real-servers-1klb)). Hidden Unicode is another case where static detection clearly works ([Embrace The Red](https://embracethered.com/blog/posts/2026/scary-agent-skills/)).

For zgScanner this evidence predicts strong scores on the poisoned-tool-description channel and near-zero scores on the four data-plane channels. The project's catalog lists 11 external scanners plus the repository's own "wiggle declared scan", labels checks with OWASP MCP01–MCP10, and offers opt-in modes beyond static rules: a pin file from an earlier run for drift detection, `--identify-as` for client switching, OSV and VirusTotal lookups, and an LLM judge that needs Anthropic credentials ([catalog.py](../wiggle/zgscanner/catalog.py)). Two consequences follow. Merging checks from scanners that barely overlap raises recall on metadata-visible issues but also stacks their false positives, so the study must report zgScanner's false-positive rate on a benign server set, not only its hits. The opt-in LLM judge reads attacker-authored descriptions, so it inherits the injectable-judge problem that the policy-generator question raises. Two catalog URLs now redirect, `getjavelin/ramparts` to [highflame-ai/ramparts](https://github.com/highflame-ai/ramparts) and `fr0gger/proximity` to [Nova-Hunting/nova-proximity](https://github.com/Nova-Hunting/nova-proximity), and the [AgentAvow scanner repository](https://github.com/AgentAvow/mcp-security-scan) is archived; the Snyk entry already points at the current repository, whose CLI no longer has the historical `proxy` subcommand ([cli.py](https://github.com/snyk/agent-scan/blob/main/src/agent_scan/cli.py)). The study should cite the commit or version each check was taken from. On rug pulls, the only documented in-the-wild MCP case, postmark-mcp, changed code rather than tool metadata ([The Hacker News](https://thehackernews.com/2025/09/first-malicious-mcp-server-found.html)), so description pinning covers a threat with little real-world evidence; the 2026-07-28 spec also removes protocol sessions and adds list caching (`ttlMs`), so pinning has to work with cached lists ([MCP changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)).

### Server checks failed inside the study's own servers

Layer (b) has the cleanest story and the trickiest definition. The filesystem and git reference servers both shipped missing-containment bugs (cited above), and MCP-FSD's two git CVEs are among them; the same paper's memory-server finding is a configuration injection through a launch-time persistence path, fixed upstream without a CVE, and not entity-content injection; it reports no fetch or time findings ([arXiv](https://arxiv.org/html/2610.22301)). Operating-system isolation works where the server's own check fails: a sandbox with read-write access only to the working directory blocked **all 150** validated MCP-FSD instances that leaked the planted secret unsandboxed ([arXiv](https://arxiv.org/html/2610.22301)). The MCP specification's security best-practices page covers authorization and infrastructure (confused deputy, token passthrough, SSRF in OAuth discovery, local server consent) and **does not treat prompt injection or tool poisoning as an attack category** ([MCP](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)), so spec-compliant checks do not defend against the study's injections by themselves. Check Point's Black Hat USA 2026 work shows why (b) still matters: 11 vulnerabilities in agent frameworks were classic deserialization, SSRF and path-traversal bugs reached after injection, and "reading the wrong document is enough" ([The Register](https://www.theregister.com/security/2026/08/05/prompt-injection-isnt-the-bug-ai-agent-frameworks-are/5283585)). By definition the deployed check failed in all 23 boundary-break incident rows, because each bug *is* a missing or wrong check, so the study must say whether (b) means "as shipped" or "as patched". Every agent-in-path boundary break in the catalogue could in principle also be stopped earlier by (c), (d) or (e); that is a testable claim, not a finding.

### The "Needed" ladder has a 30-year lineage and two 2026 neighbours

Learning least privilege from observed behavior is old. Forrest et al. profiled normal system-call sequences in 1996 ([IEEE S&P 1996](https://www2.cs.uh.edu/~acl/cs6397/Doc/1996-IEEE%20SP-A%20Sense%20of%20Self%20for%20Unix%20Processes.pdf)); Systrace generated call-and-argument policies in a training session ([USENIX Security 2003](https://www.usenix.org/conference/12th-usenix-security-symposium/improving-host-security-system-call-policies)); AppArmor's `aa-genprof` turns complain-mode logs into path rules ([man page](https://manpages.debian.org/man/8/aa-genprof)); AWS IAM Access Analyzer writes policies from CloudTrail activity ([AWS](https://aws.amazon.com/blogs/security/iam-access-analyzer-makes-it-easier-to-implement-least-privilege-permissions-by-generating-iam-policies-based-on-access-activity)). The same lineage documents the ladder's core weakness: dynamic training misses rare but legitimate paths, which Confine answered with static over-approximation ([RAID 2020](https://researchconnect.stonybrook.edu/en/publications/confine-fine-grained-system-call-filtering-for-container-attack-s/)) and Chestnut with hybrid static-plus-dynamic refinement ([arXiv](https://arxiv.org/pdf/2012.02554)). The ladder maps cleanly onto this history: L1 "declared" resembles a manifest, L2 a tool allowlist, L3 an AppArmor-style path profile, and L4/L5 Systrace-style argument filters.

Agent-era neighbours sit on both sides of the ladder. AgentBound (FSE 2026) has an LLM pipeline write Android-style manifests from server code and enforces them in a Docker container; this is the closest analogue of L1, and by its own account it does not stop parameter tampering on a permitted endpoint or injections that only change reasoning ([arXiv](https://arxiv.org/html/2510.21236v3)). AgentDojo's `tool_filter` is a crude L2: it cuts gpt-4o ASR to **6.84%** ([AgentDojo results](https://agentdojo.spylab.ai/results/)) but collapses Llama-3.3-70B benign utility to **4.12%** ([arXiv](https://arxiv.org/html/2502.05174v4)). Permission Denied ran 12 coding agents under nested, hand-defined restriction levels; the strictest cost **18.3 points of task success and 167.3% more cost**, and blocked agents ran to timeout or produced wrong answers, with no injection tested ([arXiv](https://arxiv.org/abs/2608.02670)). The research notes disagree on novelty here. One pass found no agent-era system that learns policy from benign traces; a second found two from 2026. Dang's behavioral firewall compiles verified benign tool-call telemetry into a parameterized automaton, reports **5.6% macro ASR on ASB**, and admits **18% evasion** of its continuous parameter bounds by synonym substitution ([arXiv](https://arxiv.org/abs/2604.26274)); AgentGuardian learns access-control policies from staging traces and notes that a weaker orchestrator's planning errors carried into the traces and weakened the policies ([arXiv](https://arxiv.org/abs/2601.10440v1)); TraceAegis learns behavioral rules from traces for anomaly detection ([arXiv](https://arxiv.org/abs/2510.11203)). The second pass is the more complete, so the novelty claim must narrow: trace-learned agent policies exist, but a nested L0–L5 ladder learned from benign MCP traces, plotted as strictness against held-out utility on shared injection traces and compared with four other layers, does not.

### Task-conditioned policies are the best-measured layer

Progent is the reference for layer (d). An LLM writes symbolic rules over tool names and arguments from the user task, every call is checked deterministically, and a Z3 subset check auto-applies narrowing updates while routing expansions to an approver. It cut AgentDojo ASR from **39.9% to 1.0%** (2.5% with the initial policy alone), ASB from **70.3% to 3.9%**, and stayed "around 1%" in an MCP proxy mode across four agent frameworks ([arXiv](https://arxiv.org/html/2504.11703v3)). Its stated limits matter to this study: it offers no defense for attacks that stay inside the task's least privilege, and its MCP proxy cannot protect built-in tools that bypass MCP. An independent replication on Qwen2.5-7B saw utility under attack fall from about 45% to about 26% ([arXiv](https://arxiv.org/html/2606.26479)). Conseca generates a just-in-time policy from trusted context only; on 20 tasks it completed **12.0** against 14.0 with no policy, 12.2 with a static permissive policy and **0.0** with a static restrictive one ([arXiv](https://arxiv.org/html/2501.17070v3)), a tiny precedent for the study's strictness curve. DRIFT (NeurIPS 2025) plans a function trajectory with parameter checklists ([arXiv](https://arxiv.org/html/2506.12104v3)); MiniScope picks the cheapest OAuth-style scope set that covers a plan and reports that LLM least-privilege choices reach only 70–83% optimality for proprietary models and 20–34% for open ones ([arXiv](https://arxiv.org/pdf/2512.11147)); AuthBench finds frontier models both omit needed permissions and grant unused, sensitive ones ([arXiv](https://arxiv.org/abs/2605.14859)). The only public vendor error rates for a learned permission policy come from Anthropic's Claude Code auto mode: **0.4% false positives on 10,000 real actions, 17% false negatives on 52 real "overeager" actions and 5.7% on 1,000 synthetic exfiltration cases**, with a classifier that sees only user messages and bare tool calls, "reasoning-blind by design" ([Anthropic](https://www.anthropic.com/engineering/claude-code-auto-mode)). Expect (d) to miss attacks whose harmful sink the task itself needs, such as "reply to this ticket", which is the shape of the Atlassian and Supabase incidents ([Cato CTRL](https://www.catonetworks.com/blog/cato-ctrl-poc-attack-targeting-atlassians-mcp/); [Willison](https://simonwillison.net/2025/Jul/06/supabase-mcp-lethal-trifecta/)).

### Data-flow rules fit exfiltration and miss integrity

The strongest data-flow designs replace the agent loop rather than wrap it. CaMeL extracts control and data flow from the trusted query and solves **77% of AgentDojo tasks with provable security against 84% undefended** ([arXiv](https://arxiv.org/abs/2503.18813)); RTBAS prevents all targeted AgentDojo attacks with 2% utility loss under attack ([arXiv](https://arxiv.org/abs/2502.08966)); FIDES attaches confidentiality and integrity labels in a planner ([arXiv](https://arxiv.org/abs/2505.23643)). CaMeL's guarantees do not compose across agents: ASR was 12.9% without CaMeL, 0.2% with per-agent CaMeL and 0.0% with a multi-agent protocol ([arXiv](https://arxiv.org/abs/2610.05640)). These belong in the paper as an architecture baseline, not a bolt-on layer. Two MCP-native options can express "no fetch to a URL that came from tool output" today: Invariant Guardrails' `->` flow rules in a proxy or gateway ([GitHub](https://github.com/invariantlabs-ai/invariant)) and the SAMOS gateway, which taints the session with tool-level labels ([Brown thesis](https://atlas-group.cs.brown.edu/pdf/samos:brown:2026.pdf)). A rule built by matching URL values against earlier tool results will miss transformed or re-encoded URLs (inference). MITRE ATLAS already names the layer as mitigation AML.M0030, "Restrict AI Agent Tool Invocation on Untrusted Data" ([atlas-data](https://github.com/mitre-atlas/atlas-data)), and the two 2026 CVEs about attacker-supplied hosts (cited above) are its textbook fit. Deterministic egress rules also fail through stale configuration: Salesforce's ForcedLeak sent data to an allowlisted domain that had expired and could be bought for about $5 ([Noma](https://noma.security/blog/forcedleak-agent-risks-exposed-in-salesforce-agentforce/)). As specified, rule (e) guards only the exfiltration goal; reading the secret and writing the `.sh` file have no outbound sink. That gap is not academic: when editor agents wrote harmful code and then ran it, 277 of 314 outputs contained malicious patterns, so command allowlists alone did not hold ([arXiv](https://arxiv.org/html/2509.22040v1)).

| Layer | Best measured evidence | Documented blind spot | Incident rows it plausibly stops (of 40, inference) |
|---|---|---|---|
| (a) Static scanner | MCPZoo average precision 45.53%, recall 24.17% | Code-level malice, tool output, paraphrase; 51% of ACE payloads had no server to scan | about 16 |
| (b) Server checks | Sandbox blocked 150 of 150 MCP-FSD instances | In-scope misuse and supply chain by construction; as-shipped checks failed in every bug row | 23, plus 2 partial |
| (c) Trace-derived ladder | Benign-trace automaton 5.6% ASB ASR; `tool_filter` 6.84% ASR | Rare legitimate paths; attacks that reuse benign patterns | about 10 |
| (d) Task-conditioned policy | Progent 39.9% → 1.0% on AgentDojo | Tasks that need the sink; attacks inside the task's least privilege | about 14 |
| (e) Data-flow rule | CaMeL 77% vs 84% utility with provable security | Integrity-only harm; transformed values | about 17 |

The incident counts overlap (one row can count for several layers) and are inference, not measurement. 15 of the 40 rows have no agent decision, so (c), (d) and (e) cannot stop them at all.

## Two channels and the policy generator remain unmeasured

The study's five channels sit at very different levels of prior measurement.

| Channel | Published measurement | Best evidence | Value for the study |
|---|---|---|---|
| Poisoned tool description | Heavy | MCPTox up to 72.8% ([arXiv](https://arxiv.org/abs/2508.14925)); tool-metadata poisoning 89.3% ([arXiv](https://arxiv.org/html/2509.24272v1)); implicit poisoning 84.2% ([arXiv](https://arxiv.org/abs/2601.07395)) | Saturated; mainly a test bed for the scanner layer |
| Fetched web page | Yes, less | Webpage poisoning among MCPXKIT's indirect attacks ([arXiv](https://arxiv.org/html/2508.12538v2)); MSB retrieval injection ([arXiv](https://arxiv.org/html/2510.15994v2)) | External validity through the reference fetch server |
| Repo file | Only outside MCP | Rules files in coding editors: 41.1–83.4% ASR ([arXiv](https://arxiv.org/html/2509.22040v1)) | First MCP-filesystem numbers |
| Git commit message | **None** | Nearest: GitHub issue demo ([Invariant](https://invariantlabs.ai/blog/mcp-github-vulnerability)); git CVEs triggered by content the assistant reads ([The Register](https://www.theregister.com/2026/01/20/anthropic_prompt_injection_flaws/)) | Novel |
| Memory-graph entity | **None in MCP** | Non-MCP MPBench: aggressive memory writers are more exploitable ([arXiv](https://arxiv.org/abs/2606.04329)) | Novel |
| Sampling, resources, prompts (not in study) | One paper; sampling PoC only | Resource output 67.8%, prompt output 46.7% ([arXiv](https://arxiv.org/html/2509.24272v1)); sampling PoC ([Unit 42](https://unit42.paloaltonetworks.com/model-context-protocol-attack-vectors/)) | Sampling is deprecated in the 2026-07-28 spec ([MCP](https://modelcontextprotocol.io/specification/2026-07-28/changelog)) |

Model choice will not give a clean "bigger is safer" story. MCPTox reports inverse scaling: o1-mini reached 72.8% while several small models sat near 5–15%, and enabling reasoning raised Qwen3 ASR by 27.8% ([arXiv](https://arxiv.org/html/2508.14925v1)). Part of that is "cannot" rather than "will not", so a weak model looks safe unless benign utility is reported beside ASR. The host moves ASR as much as the model: swapping one host's system prompt for Cursor's cut tool-metadata poisoning from **100% to 6.7%** ([arXiv](https://arxiv.org/html/2509.24272v1)), and the same Claude 4 Sonnet scored 69.1% in Cursor against 52.2% in Copilot ([arXiv](https://arxiv.org/html/2509.22040v1)). A NIST-led competition with 250,000+ attacks hijacked every one of 13 frontier models at least once, and attacks transferred from robust models to weaker ones but not the reverse ([NIST CAISI](https://www.nist.gov/blogs/caisi-research-blog/insights-ai-agent-security-large-scale-red-teaming-competition)), which argues for building attacks against the most robust model in the pool first.

The policy-generator question is half answered. Progent treats the user query as trusted and lets an LLM updater read tool results; its Appendix E auto-approves every expansion request to model the worst user, runs three adaptive attacks (a conditional "if-then-else" injection, an appended policy-update request, and AgentVigil), and finds they "can only marginally increase the ASR" ([arXiv](https://arxiv.org/html/2504.11703v3)). An independent study framed the malicious action as a pre-authorized prerequisite to the update model and measured mean ASR of **25.8% undefended, 4.2% under Progent and 2.6% under the adaptive attack** ([arXiv](https://arxiv.org/html/2606.26479)). Conseca rests its protection on showing the generator trusted context only and tests no adaptive attack ([arXiv](https://arxiv.org/html/2501.17070v3)); DRIFT's adaptive attacks target only its injection isolator ([arXiv](https://arxiv.org/html/2506.12104v3)); the twelve defenses broken at more than 90% ASR by "The Attacker Moves Second" include no LLM-written policy system ([arXiv](https://arxiv.org/html/2510.09023v1)). Analogues show the LLM part will fall: one injection made a GPT-4.1 monitor score all **375 of 375** backdoored samples benign ([arXiv](https://arxiv.org/abs/2510.09462)), and optimized injections steer LLM judges ([arXiv](https://arxiv.org/abs/2403.17710)).

What stays open, and is defensible as new, is injection at policy birth. Untrusted text inside the user turn (a pasted README, an issue, a commit log the user asks the agent to act on) reaches the *initial* generator. Progent's SMT gate compares a new policy against the old one, and an initial policy has no predecessor, so a widened initial policy never reaches an approver. CaMeL, Progent and Conseca all share the trusted-user-prompt assumption that this attack targets. Four further variants are unmeasured: a joint injection that must both hijack the agent and widen the policy, following the multi-objective method of Zhan et al. ([arXiv](https://arxiv.org/html/2503.00061v2)); strong attackers on the policy model, such as RL-trained injectors ([arXiv](https://arxiv.org/html/2510.04885v1)) or tree-search red-teaming ([arXiv](https://arxiv.org/abs/2505.05849)); auto-applied narrowing abused as a denial of service; and persuasion of a human approver. No benchmark scores "policy over-permission against ground-truth least privilege". The study already owns a candidate ground truth: the L5 exact envelope for the same task. One unverified lead, "Agent Approval Laundering", should be read before any priority claim ([arXiv](https://arxiv.org/pdf/2609.28586)).

The trace-derived ladder has a matching open problem. Classic work shows learners can be poisoned at training time: deliberate noise in about half the suspicious-flow pool stopped Polygraph from producing useful worm signatures ([IEEE S&P 2006](https://ieeexplore.ieee.org/abstract/document/1623998)), and chaff traffic blinded a PCA anomaly detector ([IMC 2009](https://ptolemy.berkeley.edu/projects/truststc/pubs/725/IMC.2009.pdf)); mimicry at test time is the separate Wagner–Soto threat ([CCS 2002](https://www.cs.purdue.edu/homes/ninghui/readings/AccessControl/wagner_soto_ccs02.pdf)). No agent-era paper poisons the benign traces a policy learns from. If those traces come from live agents that read attacker-reachable content, injection during collection *is* the poisoning mechanism, the same channel as policy-birth injection.

## Practitioners argue the layer question without measurements

The essay literature frames the five layers but never measures them against each other. Simon Willison's "lethal trifecta" (private data, untrusted content, external communication) calls a guardrail that blocks 95% of attacks a failing grade ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)), which positions rule (e) and the exfiltration goal. Meta's Rule of Two allows at most two of untrusted input, sensitive access and state change per session, and says it supplements least privilege rather than replacing it ([Meta](https://ai.meta.com/blog/practical-ai-agent-security/)). Microsoft argues for "least agency" after its invoice example in which every step was authorized ([Microsoft](https://www.microsoft.com/en-us/security/blog/2026/06/30/securing-ai-agents-ai-tools-move-from-reading-acting/)). Kellogg's red/blue "MCP Colors" labels ([Willison](https://simonwillison.net/2025/Nov/4/mcp-colors/)) and Invariant's Toxic Flow Analysis ([Invariant](https://invariantlabs.ai/blog/toxic-flow-analysis)) turn the trifecta into static capability checks, which zgScanner's "capabilities & toxic flows" category mirrors. The multi-lab design-patterns paper gives the vocabulary for task-conditioned restriction ([Willison](https://simonwillison.net/2025/Jun/13/prompt-injection-design-patterns/)), and work on role confusion shows that "destyling" injected text cut attack success from 61% to 10%, a reason for pessimism about content-level detection ([Willison](https://simonwillison.net/2026/Jun/22/prompt-injection-as-role-confusion/)). Vendor stacks are uniformly layered and probabilistic-plus-deterministic: Google ([Google](https://security.googleblog.com/2025/06/mitigating-prompt-injection-attacks.html)), Microsoft ([MSRC](https://www.microsoft.com/en-us/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)) and OpenAI, which trains an RL attacker and says the problem may never be fully solved ([OpenAI](https://openai.com/index/hardening-atlas-against-prompt-injection/)). The learned-permission debate is live: Willison distrusts non-deterministic classifiers and wants a sandbox by default ([Willison](https://simonwillison.net/2026/Mar/24/auto-mode-for-claude-code/)), and Rehberger got Claude Code's auto mode to approve a download whose planted `struct.py` then ran, with about 80% reliability ([Embrace The Red](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)), a reminder that the study must define what counts as a "stop".

Talks and videos are fewer than the essays. The best recorded talk is Rehberger's 39C3 "Agentic ProbLLMs", a catalogue of coding-agent exploits ([media.ccc.de](https://media.ccc.de/v/39c3-agentic-probllms-exploiting-ai-computer-use-and-coding-agents)); Willison's lethal-trifecta talk has annotated slides ([Willison](https://simonwillison.net/2025/Aug/9/bay-area-ai/)). Zenity's AgentFlayer at Black Hat USA 2025 showed zero-click connector injections including Cursor with Jira MCP ([the-decoder](https://the-decoder.com/agent-based-ai-systems-face-growing-threats-from-zero-click-and-one-click-exploits/)). Black Hat USA 2026 moved to "assume injection": Check Point's post-injection framework bugs ([The Register](https://www.theregister.com/security/2026/08/05/prompt-injection-isnt-the-bug-ai-agent-frameworks-are/5283585)), Roblox's "Caging the Agent" sandbox response to a GitHub-issue credential leak, Ben-Gurion's LLMFirewall rules over LLM traffic, and Zenity's skill-detonation framework ([Straiker](https://www.straiker.ai/blog/black-hat-usa-2026-ai-security-talks)); at Nullcon Berlin 2025, CyberArk presented poisoning through tool outputs and error strings ([Nullcon](https://berlin2025.nullcon.net/berlin-2025/speaker-speaker-your-mcp-server-executes-commands)). No verified 2025–2026 MCP recordings were found from DEF CON, RSAC or USENIX Enigma, and official Black Hat schedule pages could not be opened. Podcasts are thin and Willison-centred, such as Screaming in the Cloud ([Willison](https://simonwillison.net/2025/Aug/13/screaming-in-the-cloud/)) and Lenny's Podcast ([Willison](https://simonwillison.net/2026/Apr/2/lennys-podcast/)); none compares layers.

Frameworks supply the trace labels. The OWASP Top 10 for Agentic Applications (published 2025-12-09) separates ASI01 goal hijack, ASI02 tool misuse within authorized privileges and ASI03 identity and privilege abuse ([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)); the category names come from secondary pages such as an ASI02 explainer ([Galileo](https://galileo.ai/blog/owasp-agentic-ai-asi02-tool-misuse)) and need checking against the PDF. ASI02 is the in-scope-misuse class by name. The OWASP MCP Top 10, which zgScanner already uses, is still a beta list ([OWASP](https://owasp.org/www-project-mcp-top-10/)); CoSAI's draft MCP paper defines threat categories MCP-T1 to T12 ([CoSAI](https://www.coalitionforsecureai.org/wp-content/uploads/2026/03/model-context-protocol-security-1.pdf)); ATLAS technique AML.T0086 notes that the invoked exfiltration tool "may be legitimate" ([atlas-data](https://github.com/mitre-atlas/atlas-data)). One piece of counter-evidence deserves a citation in the threat model: about 6,000 email-borne injection attempts against an Opus 4.6 agent in the HackMyClaw challenge leaked no secrets ([Willison](https://simonwillison.net/2026/Jun/26/hack-my-ai-assistant/)).

## Redesign the study around attribution validity

Four validity threats dominate, and each has a concrete fix. Construct validity: the canary goals make in-scope misuse true by construction, so the goals need boundary-crossing alternatives and the hypothesis must be stated conditional on patch status. Counterfactual validity: offline replay assumes a blocked call ends the attack, but agents re-plan after a denial (Conseca feeds denials back to the planner) and blocked agents can time out or return wrong answers ([arXiv](https://arxiv.org/abs/2608.02670)), so a live re-run sample per layer has to check the replay. Label validity: a grader that sees the condition corrupts labels, as the 58 flipped labels showed ([arXiv](https://arxiv.org/abs/2608.12880)). Attacker strength: static attacks overstate defenses, and adaptive attacks broke 12 published defenses at more than 90% ASR, most of which had reported near-zero ([arXiv](https://arxiv.org/abs/2510.09023)). The table turns this into decisions.

| Change | Evidence that motivates it |
|---|---|
| Run the main arm on patched reference servers and one arm on known-CVE versions; state the hypothesis as "after patching, residual successes are in-scope misuse" | The tallies diverge on patch status; both reference servers shipped containment CVEs ([GHSA](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-vjqx-cfc4-9h6v)) |
| Give each canary goal a boundary-crossing alternative (secret outside the root, write outside the allowed directory, out-of-repo `git_add`) | Benchmark metrics that require legitimate-tool misuse inflate the in-scope share ([arXiv](https://arxiv.org/html/2508.14925v1)) |
| Code every successful trace with three yes/no fields (inside the tool's declared scope? inside the user's or host's grant? needed a bug?) plus an OWASP ASI01/02/03 label; flag borderline cases such as any-host fetch | No paper labels traces; CNAs now treat any-host arguments as bugs ([CVE-2026-18655](https://www.cve.org/CVERecord?id=CVE-2026-18655)) |
| Define layer (b) as "as shipped" or "as patched" before scoring | As-shipped checks failed by definition in all 23 bug rows |
| Exclude attack classes with no agent decision, or report them as reachable only by (a) and (b) | 15 of 40 incident rows have no agent in the path |
| Learn the ladder on training tasks; score on held-out tasks and held-out injection templates | Universal attacks transfer to unseen tasks and domains ([arXiv](https://arxiv.org/abs/2606.10525)) |
| Report first-blocker, every-blocker and unique-blocker attribution, and validate replay with live re-runs per layer | Blocked agents re-plan, time out or answer wrongly ([arXiv](https://arxiv.org/abs/2608.02670)) |
| Use deterministic state oracles blind to condition, and a local HTTP sink for the fetch canary | 58 labels flipped under condition-blind regrading ([arXiv](https://arxiv.org/abs/2608.12880)) |
| Report benign utility, utility under attack and ASR with Wilson intervals over at least 3 runs; compare layers with paired tests such as McNemar | Run-to-run variance is large: pass@1 52.56% vs pass^4 33.86% ([arXiv](https://arxiv.org/html/2509.24002v1)) |
| Fix and report the host system prompt, approval mode and tool-result framing | A system-prompt swap moved ASR from 100% to 6.7% ([arXiv](https://arxiv.org/html/2509.24272v1)) |
| Report zgScanner's false-positive rate on benign servers and its marginal catch once (e) is active | Scanner overlap is 15.66%; audits found heavy false positives ([arXiv](https://arxiv.org/html/2607.11086v1)) |
| Add one adaptive round against the strongest layer with a stated query budget; call static ASR a lower bound | 12 defenses broken at more than 90% ASR ([arXiv](https://arxiv.org/html/2510.09023v1)) |
| Attack the policy generator at birth and in the updater as separate arms; report "policy widened" and "action executed" separately; measure over-permission against L5 | Updater attacks are covered with a negative result; birth is untested ([arXiv](https://arxiv.org/html/2606.26479)) |
| Add a poisoned-collection arm for the ladder | No agent-era study poisons benign training traces ([IEEE S&P 2006](https://ieeexplore.ieee.org/abstract/document/1623998)) |
| Pin the MCP spec version and say which component a rug-pull fixture changes (metadata, code or remote behavior) | The 2026-07-28 spec removes sessions and deprecates sampling ([MCP](https://modelcontextprotocol.io/specification/2026-07-28/changelog)); the in-the-wild rug pull changed code ([The Hacker News](https://thehackernews.com/2025/09/first-malicious-mcp-server-found.html)) |

Two smaller choices follow from the model evidence. Pick at least one open-weight model so that white-box attacks on the policy generator are possible, which the independent Progent study names as open ([arXiv](https://arxiv.org/html/2606.26479)), and build attacks against the most robust model first. Report each layer alone and stacked, because LlamaFirewall's combination bought diminishing ASR gains at an additive utility cost ([arXiv](https://arxiv.org/html/2505.03574v1)).

## Conclusion

The study's strongest contribution is not a sixth defense but a measurement that ends a definitional dispute. "Most injections are in-scope misuse" is true of benchmarks and false of the CVE record because each population defines success in a way that selects one class; a per-trace label on patched and unpatched servers, with goals that offer both paths, converts the argument into a number that neither literature can produce. The same logic predicts the attribution table's shape: (b) dominates the vulnerable arm, (a) dominates the tool-description channel, and the residual on patched servers falls to (d) and (e), with (e) structurally blind to the read and write goals. If the measured table departs from that prediction, that is the more interesting result.

The policy-generator question generalizes beyond Progent. Layers (c) and (d) both turn text into policy, one from benign traces and one from the task description; both fail by coverage (rare paths, tight-but-brittle policies), and both can be attacked at construction time through the same channel: untrusted content present when the policy is built. Framing "injection at policy birth" and "poisoning of trace collection" as one threat (policy-construction injection), measured with an over-permission metric against the study's own L5 envelope, gives the paper a novel thread that the updater-focused prior work leaves open. Novelty claims still rest on non-exhaustive searches, so ROPE, AgentArmor and the "Agent Approval Laundering" lead need reading before submission.
